### 不建议做的大学方向

- **纯数学的分析/代数**（实分析、抽象代数、拓扑）：命题的证明过程不是「给定参数
  → 输出数值」的函数，图只能承载直觉而非论证 → ③ 为主。做也只能做有限的特例演示。
- **文科与社科的理论课**：同 `coverage-audit.md` 的 ③ 结论。
- **依赖不可复现实验的科目**：违反「动画必须真跑」纪律。

## 三·补、经济学的可行性（新增）

**结论：可以做，而且可算比例不低** —— 但必须像 `edu-history` 那样**标注证据力等级**，
因为「经济模型」与「经济预测」是两件完全不同的事。

**可算且有教学价值的部分（①）**：

| 主题 | 内核 | 等级 | 说明 |
| --- | --- | --- | --- |
| 供需均衡与消费者/生产者剩余 | 线性/非线性供需求交点 + 定积分 | ①A | 纯数学；剩余是积分，图上面积可精确算 |
| 弹性（价格弹性、弧弹性） | $\varepsilon = \frac{dQ}{dP}\frac{P}{Q}$ | ①A | 纯导数 |
| 复利、现值、年金 | $(1+r)^n$、$\sum$ 等比 | ①A | 恒等式；与 `edu-history` 的翻倍时间同源 |
| 索洛增长模型 | $\dot k = sf(k) - (n+g+\delta)k$ | ①A | 有稳态解析解；与 `edu-ode-dynamics` 同工具箱 |
| Cobb–Douglas 生产函数 | $Y = AK^\alpha L^{1-\alpha}$ | ①A | 边际产量、规模报酬、欧拉定理都可精确算 |
| 垄断定价与边际收益 | $MR = p(1+\frac1\varepsilon)$ | ①A | 纯代数 |
| 拉弗曲线 | 税收 $= \tau \cdot B(\tau)$ | ①A | 有明确最优点 |
| 消费者选择（预算约束 + 效用） | 拉格朗日乘子 | ①A | 与多元微积分同源 |
| 囚徒困境/纳什均衡（2×2） | 最优反应求交 | ①A | 离散、可穷举，无争议 |
| 乘数效应 | $\frac{1}{1-c(1-t)}$ | ①A | 等比级数 |
| 基尼系数 | 洛伦兹曲线下的面积 | ①A | 定积分，图上面积精确 |
| 市场出清的网络流/运输问题 | 线性规划 | ①A | 可精确求解 |

**必须标注为 ①B / ③（不可独立验证）的部分**：

- 任何含**估计参数**的模型（索洛的 $s$、$n$、$g$、$\delta$；需求弹性；乘数里的边际消费倾向）
  —— 内核确定，参数靠估，**形态是 ①、证据力是 ③**。
- **政策效果预测**（减税会怎样、加息会怎样）—— 参数与因果都不可独立验证，
  与 `edu-history` 的「王朝周期」同级，必须显式标注。
- **福利经济学的最优性论断**——模型内部的结论，不能当作现实结论。

**明确不做**：计量经济学的回归推断（那是统计课）、博弈论的一般理论（要证明）、
经济思想史（叙事）、以及任何需要真实宏观数据表的内容（那属于 ①B 数据页，
要走出处/许可/指纹一整套流程）。

**与已有技能的边界**：`edu-probability`（统计推断）、`edu-ode-dynamics`（动态系统）、
`edu-linear-algebra`（投入产出表、线性规划）—— 经济学技能应**复用**这些工具箱，
只新增经济学的**场景与结论**，不重复实现数学。

**建议的 7 个题型**：`supply`（供需与剩余）· `elasticity`（弹性）·
`growth`（索洛稳态）· `cobb_douglas`（生产函数与边际）· `monopoly`（垄断定价）·
`nash`（2×2 纳什均衡）· `gini`（洛伦兹曲线与基尼系数）。

> **初高中收尾已全部完成。** 下一步进大学线。

**`edu-history` 的特殊纪律**：历史学的立身之本（史料批判、因果论证、动机推断）
落在 ③ 层，不可形式化。所以该技能只做 ① 层，并**强制每一页标注证据力等级**：
①A 纯数学/恒等式、①B 模型参数靠估、①C 形态①证据力③（可被拟合，最危险）。
没有徽章的页不许出 —— `_evid_badge()` 在构建期强制。

**已确立的三个可复用机制**（后续技能照用）：
1. **读数表达式 ↔ 内核逐条对账**：`generate.py` 里的 `_agree()` 在构建期用等价的
   Python 实现求值一次再比对，公式漂移当场停构建。经验证它已三次抓到真错
   （JS 的 erf 逼近漏了除以 √2；`_js_to_py` 需要剥外层括号才能递归三目；
   `declination(172)=23.4398` 与常量 23.44 的 2e-4 偏差）。
2. **跨语言逐位一致的伪随机**（32 位 LCG）：让浏览器里随滑块重跑的模拟
   与内核录下的是**同一条随机序列**。`edu-probability` 的实测证据：
   大数定律末值 0.49145 == 0.49145，CLT 样本均值差 0.0e+00。
3. **模拟量在浏览器真跑、理论量由内核现算**：两者用同一个输入契约，
   读数只放理论值，图上只放真跑结果 —— 避免两套实现互相漂移。

**已经踩过、必须显式检查的四类坑**：
1. 模板里「参数驱动的字段」要写成参数字符串（如 `"n": "n"`）。漏写会让画板拿到
   `undefined` 抛错，而 `render()` 在 `updateReadouts` 之前中断 ——
   读数全变「—」，看起来像「没数据」而非「有 bug」。`edu-chem-calc` 抓到过。
2. **取整语义**：Python 的 `round()` 是银行家舍入，JS 的 `Math.round` 不是。
   涉及取整一律写 `floor(x+0.5)`。`edu-geography` 的时区号抓到过。
3. **滑块 `value` 必须落在 `step` 网格上**：不自洽时浏览器会**悄悄吸附**初始值，
   页面上「题设值」根本拖不到。自检要读回 `input.value` 核对。
   `edu-geography` 的默认经度因此从 87.6° 改成 116°。
4. **长注释顶出画布**：右侧一列用 `start` 对齐的文字最容易溢出；
   自检要量像素包围盒的四周余量，不能只看「有没有内容」。
   `edu-probability`（探测点标签）、`edu-chem-calc`（55 字注释）、
   `edu-geography`（换算说明）各抓到一次。
   **已给出通用修法**：`edu-history` 的 `labelIn()` —— 先按当前 `sc`
   用 `ctx.measureText` 量宽，再按对齐方式把锚点收进画布。后续技能请直接用
   `labelIn`，不要再手工试位置。
5. **只在默认档自检会漏**：`edu-history` 的 `transition` 页峰值标签**只在滑块低端**
   才顶出画布。自检必须扫多个档位（至少含两端）。
6. **状态灯文案是纯文本**：`updateReadouts` 用 `textContent` 写入读数，
   `$…$` 不会被 KaTeX 渲染，会原样显示成 `$R_0$`。状态文案不要写 LaTeX。
7. **滑块的参数范围必须落在模型的有效域内**：`edu-history` 的 `transition`
   把 `mid_b` 下限从 1900 收到 1930 —— 低于 1920（死亡率中点）时模型前提被破坏，
   增长率从窗口起点就单调下降，「峰值年」退化成窗口边界（那是产物，不是结论）。
   **看下限的一条通用判据**：参数取到端点时，读数是否仍然是模型想说的那个量。
8. **LaTeX 花括号在「普通字符串」里不能写双份**：只有 f-string 里 `{{ }}` 才表示
   `{ }`；隐式拼接里没有 `f` 前缀的那些片段，`{{ }}` 会**原样**进入 LaTeX，
   变成「组里套组」——`\begin{{pmatrix}}` 会让 KaTeX 抛
   `Expected node of type textord, but got node of type ordgroup`，
   而整页 `throwOnError:false` 又不把它当错误。
   **通用自检**：对生成页逐个 `$…$` 片段做 `renderToString(frag,{throwOnError:true})`
   —— 只有这条能抓到。`edu-linear-algebra` 抓到 2 处（61 个字符串字面量需修正）。
9. **画几何图形必须裁剪**：线性变换会把点推到极远（剪切 k=2 时能到 ±21），
   网格直接顶出画布。`edu-linear-algebra` 给出了通用工具：`laSegClip`（线段，
   Liang–Barsky）与 `laClipPoly`（凸多边形，Sutherland–Hodgman），
   外加按可见范围自适应的 `laAxes`。后续画几何的场景请直接用这三个。
10. **三目翻译器要能处理括号内嵌套**：`edu-chem-calc` 的 `_js_to_py` 只扫顶层，
    遇到 `2-(cond?1:2)` 会失败。`edu-linear-algebra` 的版本会定位三目所在的
    括号组边界，支持任意深度。新增分段读数时请用后者。
11. **数值闭式解里的 `cosh/sinh` 是陷阱**：`edu-ode-dynamics` 的过阻尼解写成
    $e^{-\zeta t}[y_0\cosh(\omega_h t)+\cdots]$ 时，$\omega_h t=848$ 直接
    `OverflowError`，而且它是两个巨大指数项相减、数值上也不稳。要改写成两个
    指数项**之和**。**通用判据**：闭式解里凡出现 `cosh/sinh` 或两个大数相减，就该改写。
12. **不稳定平衡点附近的轨道会指数发散**：`edu-ode-dynamics` 的相平面在 $k>0$ 时
    轨道 14 年能涨到 $10^6$，不裁剪就直接冲出绘图框。已给出
    `plotPolyClip`（世界坐标下的折线裁剪），画轨道时一律用它。
13. **花括号问题已入闸门**：`check_skills.py` 新增 `brace_literal_check()` ——
    对每个技能的 `scripts/generate.py` 用 tokenize 扫非 f-string 字符串，
    查 `\\begin{{` / `\\end{{`。判据**刻意收窄**：实测（KaTeX 0.16.8）只有环境名
    这一处会失败，`\\mathbf{{v}}`、`\\dfrac{{a}}{{b}}`、`\\operatorname{{tr}}`、
    `x^{{2}}`、`\\sqrt{{10}}`、`\\text{{abc}}` 这些「组套组」**全部正常** ——
    过宽的判据会把一批渲染正常的技能误报成坏（第一次实现时误报了 14 个）。

14. **触发词路由已入闸门**：`check_skills.py` 的 `check_skill_docs()` 新增
    `check_trigger_routing()`，把「选错技能」的两大来源机器化：
    ① **触发词冲突** —— 同一个词被 ≥2 个技能声明（33 个技能共 35 个这样的词）；
    ② **悬空引用** —— 边界段里点了已不存在的技能名。
    判据的关键一步：冲突**只有在未被边界声明消解时**才算错
    （A 的不该用段点了 B，或反之，就算消解）。这样既不误报「两个技能都合理地
    用了同一个词」，又能抓住「各自都写了边界却没指向对方」的真问题。
    首次运行报出 **12 个未消解冲突 + 2 处悬空引用**，修完后清零；
    并做了负向测试（注入一个冲突 → 闸门 exit=1；恢复 → exit=0）确认不是空转。

15. **「静态校验通过」不等于「能渲染」——渲染器 bug 可以无限期潜伏**：
    `shared/viz/viz.js` 的 `Renderer.resize` 末尾写着
    `this.W = rect.width; this.H = rect.height;`，而 **`rect` 这个标识符从未定义**
    （本意是上面刚算出的 `w` / `h`）。后果是每次 resize 都抛 `ReferenceError`，
    **整张图挂不上**，画布全白。
    为什么一直没被发现：`check.py` 走的是 **Python 侧** `vizkit.validate()` ——
    它只校验图层数据（几何是否出界、文字是否重叠、颜色是否合法），
    **根本不执行 JS**。于是数据全对、闸门全绿，页面却是空的。
    书稿的 36 张图因此**从未在浏览器里渲染成功过**，横跨多次交付。
    **修法**：`this.W = w; this.H = h;`（`ctx` 已按 `dpr` 缩放，逻辑尺寸就是 CSS px）。
    **通用教训**：只要产物里含 JS，就必须保留至少一条**真机路径**
    （本项目是 `tools.browser.tabs.open` + `evaluate` 数非透明像素 + 读 console）；
    且验证判据要**逐图比较绘制像素数与画布尺寸**，不能只看「有没有 canvas 元素」——
    canvas 元素一直都在，空画布也有 canvas。
    **影响范围**（已核实）：`viz.js` 只被 `books/math-thought`（内联进每一章）
    与 `shared/viz/page.html`（共享查看页）使用，**只有这两处受影响**；
    各技能的画板走 `vizkit.py` 的 Python 移植 + 技能自带画板 JS，不经过 `viz.js`，
    因此不受影响（它们此前已逐档真机验证过）。
    **已机器化（2026-10）**：光靠「记住要真机验证」挡不住下一次同类 bug，
    所以把它做成了闸门 —— `tools/check_render.py`（+ `viz_smoke.js` / `page_smoke.js`），
    用 node + 最小 DOM 桩**真的执行**渲染路径，分三层判据：
    ① 不抛异常；② 逻辑尺寸与「必须真的产生绘制调用」（挡住静默全白）；
    ③ 推进多帧时**每帧指纹必须互不相同**（挡住「画布纹丝不动」）。
    三个陷阱值得记下来，都是**闸门自己差点变成摆设**的地方：
    探针写成 `typeof n`（对字符串恒为 `"string"`，帧推进从未真正执行）；
    指纹只哈希方法调用参数，漏掉 `fillStyle`/`strokeStyle` 赋值 ——
    而本项目大量画板的帧间差异**只体现在换色上**（`mst` / `tree_traversal` 当场误报）；
    负向测试用「往真实产物里注错」会假通过（异常被外壳吞掉、或抽到 3D 页被 skip），
    改用**合成夹具**（抛异常 / 全白 / 纹丝不动 / 健康对照）逐条对应判据才可靠。
    第四个陷阱更隐蔽：**产物比源码旧**时，闸门测的是旧货、然后报绿 ——
    那比没有闸门更危险，因为它给了「已验证」的错觉。所以闸门按 mtime 比对
    产物与它的源码集合（该技能的 kernel/generate/template + 共享骨架 + `viz.js`/`vizkit.py`），
    陈旧即报错（`RENDER_SMOKE_BEHIND_OK=1` 才降级为警告）。
    上线时它立刻抓出真问题：`skills/*/output/` 有 6–7 天没重生成，此前那轮
    「92 页全绿」验的全是旧产物。
    现已接入 `check_skills.py` 第 8 项（跑**刚生成的临时产物**，全新克隆也能执行），
    覆盖 viz 43 图 + 技能 292 页 + 书稿 11 页 + `mental-models` 19 页 = **365 个被测物**，
    本机 `python tools/check_render.py --selftest` → 0 错误，负向测试全红/全绿；
    25 个 Three.js/WebGL 页显式 SKIP 并被点名**仍需真机浏览器验证**。

16. **「自包含」被当成口号之后，闸门也跟着自相矛盾**：
    `check_output.py` 的注释写着「产物必须断网可开，引了 CDN 就不是自包含」，
    紧接着的 `CDN_ALLOW` 却放行了 3 个 CDN（`cdn.tailwindcss.com` /
    `cdn.jsdelivr.net` / `cdnjs.cloudflare.com`）。实测（2026-10）：
    **346 个已构建产物几乎每页 4 个外部资源**（Tailwind + KaTeX 的 css/js/auto-render；
    另有 2 个共享模板同样如此），
    另有 3D 页引 Three.js。也就是说，断网时页面**能打开、文字读得到，但排版整体塌掉、
    公式显示为 LaTeX 源码**，画板因布局塌陷还可能错位 —— 而 README 与 30+ 处 SKILL.md
    都写着「自包含」（research 文档里更直接写成「断网可开」）。
    **陈述比代码更早失真**，闸门白名单让它长期无人质疑。
    处置：① 把判据与文档改成事实（白名单改名并写清取舍；`check_output` 汇总行报出
    「N 页依赖外部资源」；README/research 的「断网可开」改为「单文件、双击可开；
    排版与公式走 CDN」）；② 真要离线，得把**编译后的 CSS** 内联、KaTeX 连字体
    一起自带 —— 那是独立工程，不是顺手补丁，且必须有像素级视觉回归才敢动。
    教训：**白名单就是「已批准的不一致」**。批准可以，但必须同时改掉那句
    「引了 CDN 就不是自包含」的说明，否则下一个人会以为闸门已经保证了离线可用。
    **后续（2026-10-21）：Tailwind 已真离线** —— 用 CLI 把实际用到的类编译成
    36KB 静态 CSS（`shared/board/tailwind.min.css`，MIT，`VENDOR.md` 记来源与 sha256），
    由 `skillkit.inline_assets()` 内联。每页 60KB → 96KB，换掉 407KB 的运行时，值。
    注入位置必须与 Play CDN 一致（`</head>` 末尾）：放到原 `<script>` 位置会让
    页面自带 CSS 反过来压过 preflight，书稿整页高度当场漂 85px —— 这种差异
    **静态检查、渲染冒烟都看不见**，只有「逐元素比对 30 项计算样式」才抓得到。
    验证结果：7 个代表页里 5 个 0 差异；`edu-chem-reaction` 有 3 个步骤徽章差 1.6px
    边框（Play CDN 的 JIT 漏编译了运行时插入元素的 `border-2`，静态版更忠于源码）。
    仍未离线：**Three.js（3D 页）** —— 页面空白是更严重的退化，但 3D 页的离线要连
    模型/几何一起内联，且这 25 页目前连真机视觉验证都还没做（渲染闸门 SKIP 点名），
    没有验证手段就不该先动。KaTeX 见第 17 条（已实测，决定保留 CDN）。

17. **KaTeX 保留 CDN 是实测结论，不是「没做完」**（2026-10-21）

    动机：上一条把 Tailwind 离线化了，剩下最显眼的就是公式。于是把账算清楚，
    而不是再凭感觉说「代价大」。

    **实测**（KaTeX 0.16.8，jsdelivr 包本身）：`katex.min.js` 276,862 B +
    `katex.min.css` 23,112 B + `auto-render` 3,478 B + 20 个 `*.woff2` ≈256 KB
    （base64 后 ≈341 KB）→ **单页 ≈637 KB，346 页 ≈215 MB**。

    四个候选与取舍：

    | 方案 | 单文件 | 闸门 | 体积 | 结论 |
    |---|---|---|---|---|
    | A 保持 CDN | ✓ | 不受影响 | 0 | **采纳** |
    | B 全内联 | ✓ | **会被破坏**（见下） | +637 KB/页 | 否决 |
    | C 旁边放 `katex/` 目录 | ✗ | 不受影响 | 600 KB 一次 | 否决（违反「双击即开」） |
    | D 换 MathML（原生渲染，无 JS/字体） | ✓ | 不受影响 | 近 0 | **真正该做的那个**，独立工程 |

    B 被否决的**真正**原因不是 215 MB（本地产物不进 git，215 MB 不算什么），
    而是：`tools/page_smoke.js` 会**真实执行内联脚本**（`new Function(src)()`），
    那 276 KB 的 KaTeX 会在 DOM 桩下跑一遍 —— 每个公式页都会因桩不完整而报错。
    要放行就得给闸门开一个「跳过 KaTeX」的洞，那正是本项目「闸门不许空转」明令禁止的。
    **一个改动要靠给闸门挖洞才能合入，这个改动本身就不该合入。**

    D 为什么值得做：唯一同时满足「离线 + 单文件 + 体积可控」的方案。代价是把
    **动态公式**（滑块驱动、页内 JS 现算 LaTeX 字符串）的渲染路径整个换掉，
    且系统数学字体不统一（Windows Cambria Math / macOS STIX / Linux 常缺）。
    触发条件：出现真实需求要在断网环境（离线教室、阅卷机房）讲公式页时再启动。

18. **「现算」不等于「算对」：混沌内核的六版试错与两处闸门假阳性**（2026-10-22）

    第 10 章（确定性 → 混沌）全章只用一个映射 $x \leftarrow r x(1-x)$。
    但「分岔点在哪里」不能从文献抄 —— 抄来的数不随代码变化，正文与图就失去了同源。
    而算错了**不会报错**，只会给出一个很像对的答案（分岔点偏 1e-4 也照样单调、照样收敛）。

    **六版试错，每版都有明确的死因**：
    ① 纯二分数周期 —— 临界慢化：分岔点附近乘子 → −1，收敛速度趋零，
       谓词的过渡带宽达 1e-4，分岔点被算歪；
    ② mpmath `dps=40` 高精度 —— 15 分钟跑不完，构建期不可用；
    ③ 裸牛顿（不定盆） —— 跳到 $r = -1.54$ 的镜像分支上去；
    ④ Aitken $\Delta^2$ 加速 —— 它是有理映射，会把**不稳定**根变稳定：
       $r=3.1$ 明明在二周期窗口内，却收敛到不稳定不动点 $x^*$，谓词当场失去单调性；
    ⑤ 死循环 —— `lo,fl=hi,fh` 写在 `hi=lo+(hi-lo)*2` 之前；
    ⑥ 定论：**普通迭代定盆 → 牛顿精修 $g(x)=f^n(x)-x$ → 验收三连**（$|g|<10^{-11}$、
       $n$ 点互不相同、$|$乘子$|<1$）→ 二分 56 次求窗口右端。

    验收**不靠「跟文献对一遍」**（那样内核与文献同错就查不出来），而靠两条内生判据：
    分岔点严格递增；端点乘子回代**精确等于 −1** —— 后者是翻倍分岔的**定义**，
    与二分过程完全独立。结果：$r_1..r_7$，前六个与文献吻合到 12 位，端点乘子全部
    −1.000000000；$\delta$ 比值 4.751446 → 4.669132；
    自校验 $\lambda(4)=0.6933$ vs $\ln 2 = 0.693147$（6000 步采样的统计误差量级）。

    **这一轮闸门报红 614 + 20 条，但只有一类是产物错**：
    · G5（`check_geometry`）抓到**真错**：分岔图把周期窗口列归进混沌列，
      24 个采样点其实只有 3 个值，于是同一坐标被重复画了 8 遍 —— 614 条。
      修法是产物的：按列去重（2e-3 阈值），而不是放宽 G5。
    · W1（`vizkit`）抓到的是**假阳性**：`when: "k == i"` 的四档标签被两两比对，
      报「同一水平带重叠 51px」18 条。但 `viz.js` 是**逐层门控**的（`drawScene` 里
      `if (!ok) return`），互斥的两层永不同屏 —— 这句判定陈述与事实不符。
      修法不是关掉 W1，而是让它读懂闭区间：`==` / `>=` / `<=` 解析成区间，
      交集为空才算互斥；**认不出的写法一律保守照报**。
      同时补 4 条自测（互斥不报 / 同屏照报 / `k>=2` 与 `k==1` 判互斥 / 认不出的照报），
      并发现在 43 张图里它仍能抓到 2 处**真**遮挡（`r=3.4495` 与 `r=3.5441` 两个标签）
      —— 靠的是把后一个改右对齐，而不是放宽判据。
    · 第三处是渲染缺陷，不是判据问题：步骤说明用 `textContent` 写入，但
      `figures.py` 里本来就写的是 HTML（ch07 有 5 处 `<b>`、ch04/ch05 有 `**`），
      页面上把这些标签与星号**原样显示**了。改成 `innerHTML` 并把 `**x**` 折成 `<strong>`。

    教训：**闸门报红要分「产物错了」还是「判据错了」**。前者改产物，后者改判据；
    但改判据必须同时补一条「它仍然会红」的用例，否则就是挖洞。这一轮两者都有，
    而且**数目大的那一类（614）是产物错**——按「报错条数多就是判据太严」去处理，
    会把真问题一起放过。

19. **对数轴：尺度图的前提，以及「自动刻度」在对数轴上是错的**（2026-10-23）

    下一册（《万物简史》方向）要讲 10⁻³⁵ 秒到 10¹⁷ 秒这种跨几十个数量级的东西，
    图必须是对数尺度 —— 否则「1 秒」与「138 亿年」在图上没有任何区别。
    而 `vizkit`/`viz.js` 此前只有线性轴（`niceTicks` 全是线性间距）。

    做法：把对数变换放进**坐标映射**（`view.xlog/ylog` → 先取 `log10` 再线性映射），
    而不是让每张图自己把数据取对数。前者只有一个真源：所有图元（点/线/文字/刻度）
    都只写数据值；后者会让「数据已取对数」与「轴按原值标注」变成两份会漂移的真相。

    三条硬前提（E7，违反必红）：
    ① **范围与数据全为正** —— `log 0 = −∞`、`log 负数 = NaN`。此前这类坐标会抛异常
       然后被 `except` 记进「未解析」，等于「算不出来的点默认合法」；现在直接报错。
    ② **该轴的刻度必须显式给** —— `niceTicks` 按线性间距挑刻度，用在 log 轴上是错的：
       它会在 1 与 1000 之间给出 200/400/600/800，而这些点在图上并不等距。
    ③ **`xticklabels`/`yticklabels` 与 ticks 等长** —— 顺带解决 `fmtTick(1e9)`
       会写成「100000万」这种没法读的刻度文字。

    验证：`vizkit selftest` 补 4 条（合法对数轴必须绿 + 三条必须红）；真机像素级核对 ——
    在 x/y 双对数图上，点 $(10^6, 10)$ 应落在画布 2/3 宽、1/2 高处，
    实测 (676.25, 167.6) vs 理论 (676.67, 168)，误差 0.4px；
    同一行上直线出现在半宽处（525px），与 log 空间里的理论交点一致。

    这是下一册三个前提里的第三个（另两个：**事实核查闸门**、**外部数据许可登记**）。
    前提没立起来之前不开写 —— 一本讲「万物尺度」的书，最危险的失败模式是
    数字看起来精确、来源却经不起追问。

20. **事实核查闸门：正文里的数字也必须交代来源**（2026-10-23）

    「不手写数字」在本项目里喊了很久，但此前只覆盖**图形**（`figures.py` 现算）。
    正文里的年份、尺度、比例仍然可以手写，写错了没人管。而下一册讲的是「万物尺度」，
    这类书最危险的失败模式不是算错，而是**数字看着精确、来源经不起追问**：
    正文写下「138 亿年」，读者无法判断它是测出来的、推出来的、还是抄来的。

    做法：`shared/factreg.py` 四级登记（**现算 / 实测 / 文献 / 约定**），
    构造期 `claim(...)` 就按等级检查必填项（现算→复算函数；实测→出处+链接+不确定度；
    文献→出处+可核定位；约定→写明为什么只能约定），缺了当场抛错、不留到闸门。
    `tools/check_facts.py` 四条判据：

    | 代码 | 管什么 |
    |---|---|
    | F1 | 登记表自身必填项（兜住「绕过构造手改 dict」） |
    | F2 | 现算级：**真的调用** recompute 并比对登记值 |
    | F3 | 记号与登记表**双向**对齐（引用了没登记 / 登记了没人用） |
    | F4 | 正文里的未登记数字 |

    F2 是「不手写数字」的机器化形式：值不符就红，没有「大致对」。
    F4 连**年份**也不放过（「1838 年」「1799 年」都是事实），豁免只有三类：
    `$…$` 行内数学、`@@记号@@`、结构性编号（`图 10.1` / `第 8 章` / `(1)`）。
    白名单 `allow_pattern(regex, why)` 的**理由必填（≥8 字）**，否则构造期抛错 ——
    白名单就是「已批准的不一致」，批准可以，但不许无声地批准。

    自测 8 条：5 条必须红 + 2 条构造期拦截 + 1 条**必须全绿**（只测红不测绿，
    等于不知道判据会不会误伤干净的内容）。

    两条设计教训：
    · **只能靠「作者自觉登记」生效的判据，不是闸门**。所以 F3 做成双向、
      F4 做成「主动扫正文」，而不是「信任作者填了表」。
    · **未接入必须点名**。没有 `facts.py` 的书不判红（否则旧书的历史包袱会变成 CI 红），
      但闸门会明确打印「未接入任何书稿 —— 不等于书稿已被核查」，不静默跳过。

    诚实记录：现有书稿 `books/math-thought` 体检出 **228 个正文数字没有登记来源**
    （`python tools/check_facts.py --audit books/math-thought`）。
    这不是说那些数字错了，而是说它们**经不起追问**。旧书不接入这条闸门，
    但它这个数字留在案上 —— 新书必须先立闸门再开写，就是为了不重复它。

21. **数据许可闸门：三关（出处 / 许可 / 指纹）从散文变成判据**（2026-10-23）

    「复用数据集要过出处、许可、指纹三关」这条纪律早就有，但前两关只写在
    `SOURCES.md` 这类散文里靠人记得，第三关只在 `mental-models` 里做过。
    于是新数据进来时，**没有人被强制问一句：它的许可允许随书分发吗？**
    而「无 license」默认是保留权利 —— 搬了就是侵权。

    `shared/datasets.py` 把三关变成登记项，`tools/check_licenses.py` 强制：

    | 代码 | 管什么 |
    |---|---|
    | L1 | 许可判定与 `redistributable`/`attribution` 是否一致（兜住手改 dict） |
    | L2 | `local_sha256` vs **磁盘真实 sha256**（每次真算）；文件是否存在 |
    | L3 | 上游指纹格式 |
    | L4（警告） | 可分发却没给 `license_url` |

    许可判定是**白名单式**：只认明确列出的（公有领域/CC0 → 可分发不强制署名；
    CC BY\*/ODbL/MIT/Apache/BSD → 可分发且**必须署名**；含 NC/ND → 不可分发；
    **认不出的一律按保留权利处理**）。故意保守 —— 判错的代价是侵权，不是麻烦。

    上游哈希与本地哈希**不许互相顶替**：前者盖抓取时的原始数据，后者盖入库的蒸馏文件，
    中间隔着一道蒸馏，拿上游哈希比本地文件必然不符。这条常识此前只写在注释里，
    现在两个字段都是必填。

    接入真实数据（不是空转）：`mental-models/datasets.py` 登记两个数据集
    （Maddison CC BY 4.0 / USGS 美国公有领域），闸门真算两个 CSV 的 sha256 并与登记比对。
    自测 10 条：4 条构造期拦截 + 4 条判据红 + 1 条策略判定 + 1 条**必须全绿**。

    一个当场发现的错误值得记：我第一次给 USGS 那条写的 `upstream_sha256` 是**编的**
    （手打了一串像哈希的东西）。这正是这条闸门存在的理由 —— 哈希是 64 位十六进制，
    编一个看起来对的太容易了。改正时去 `data/usgs-quake-source.json` 取了真值。

    至此下一册的三个前提全部立起来：**对数轴**（第 19 条）、**事实核查闸门**（第 20 条）、
    **数据许可闸门**（本条）。可以开样章了。

22. **第二本书开张：先抽共享装配，再写样章**（2026-10-23）

    否则改了共享装配逻辑，闸门会拿旧产物报绿，那比没有闸门更糟。

    **三个当场踩到的坑**：
    ① **同名遮蔽**：库叫 `shared/facts.py`，书的登记表也叫 `facts.py`，
       于是书里的 `from facts import Registry` 会**导入自己**（循环）。库改名
       `shared/factreg.py`，从此「库」与「某本书的登记表」名字不同。
    ② **import 命中错的书**：两本书都有 `figures.py`，`import figures` 会拿到
       `sys.modules` 里的第一个 —— 第二本书悄悄用第一本的内核。所有按书的加载
       一律按路径 + 唯一模块名（`figures_cosmos`）。
    ③ **F3 判据太严**：一开始把「正文没引用」判成死条目，可插图是直接读登记表的
       （`V("day_sec")`），21 条登记里有 16 条被误报。改成「正文引用 **或** 插图/上游
       登记里出现 ≥2 次」（定义一次 + 真实使用一次）。**这不是产物错，是判据错** ——
       又一次印证第 18 条的教训：报红要先分清是哪一边错。

    样章压测结果：`fig-scale` 在 693.8×420 下 0 错 0 警；事实闸门 19 条登记
    0 错 0 警（其中现算级 9 条被**重新算过**并比对）；真机像素核对：宇宙年龄那个点
    落在 668px，理论值 668.1px。图形颜色直接编码**出处等级**（绿现算/灰约定/紫文献/橙实测）
    —— 让「这个数怎么被知道的」成为图的一部分，而不是藏在脚注里。

    **第 2 章（长度）补两条**：① E6 立刻抓到真问题 —— 最右边那行（可观测宇宙）的标签
    冲出画布 88px；修法是**靠近右边界自动右对齐**，不是缩短文字（缩短会丢信息）。
    ② 「标签拥挤」这个预期中的麻烦没有出现在标签上，而是出现在**行距被误读**上：
    地月距离与太阳直径只差半个数量级，照真实位置画会叠成一点，所以按行排 ——
    但这样一来「相邻两行 = 大小接近」就成了读者最可能的误读。于是在正文里**明说**
    这个布局决定，并加了一条 warn 块（「别把行距当大小」）。
    **图可以为了可读性撒谎式排版，但必须当场声明。** 37 条登记、0 错 0 警。

    **第 3–8 章补记**（写完八章后才看得出来的三件事）：
    · **第 7 章（概率）彻底换了图形类型**：前六章的量都是「一个数定位」，
      概率需要 (p, N) 两个数。图从阶梯换成四条形状相同、只是左右平移的曲线，
      所有曲线在 N = 1/p 处都到 1−1/e ≈ 0.63。结论：概率的「尺度」是 log N 上
      的一个平移量。**这一章也是全书唯一敢说「不需要外部数据」的一章** ——
      彩票组合数与生日问题全部现算，能自算的绝不外引。
    · **第 8 章（位置）给出了整本书的反转**：把六条轴归一化后，五个量都在前三成
      （平均 0.19），时间却在 0.86。一开始以为「人类偏小」，算完才发现 0.86 是
      **轴的形状**（时间轴从普朗克时间起算），不是人的特殊性。若把小端改成「一秒」，
      同一条寿命掉到 0.53；改成「宇宙年龄的百万分之一」，人的一生**落在轴外**。
      于是结论变成：「你在宇宙中的位置」不是事实，是必须连同坐标系一起说的陈述。
    · **同一段文字里同一个数写两遍，一定会漂移**：正文用记号渲染出 0.86，
      而图形的步骤说明里我手写了 0.87 —— F4 扫不到画布文字，是**真机读页面**才发现的。
      修法不是「小心点」，是让步骤说明也从登记表取值。
    F4 在这一轮里一共抓出 20 处手写数字（第 7 章 7 处、第 8 章 10 处 + 两处算错的
    对照值），而「算错的对照值」（0.98 与「0.5 附近」）是**记号和判据都拦不住**的
    那一类 —— 它们只能靠先算再写：把候选值写成一个 现算 登记，让闸门替你核对。

23. **干净克隆自检：一个只在别人机器上出现的 bug**（2026-10-25）

    改完共享模块（`bookbuild` / `vizkit` / `factreg` / `datasets`）后，光本机全绿不够 ——
    本机是**偏置样本**：产物已经存在、数据文件从未被 git 改写、字体副本也早就同步过。
    所以加了一条流程：`git clone` 到临时目录，重跑 build + 全部闸门。

    第一次跑就抓到真 bug：**数据集的 sha256 跨机器失效**。
    `core.autocrlf=true` 会在 checkout 时把 CSV 的 LF 换成 CRLF（62853 → 65042 字节），
    于是 `local_sha256` 在任何新克隆上都对不上，`check_licenses` 的 L2 判据直接红 ——
    而且报的是「文件被换过或登记写错」，看起来像数据出了问题，实际是 git 的换行转换。
    修法不是「换台机器重新算哈希」（那等于指纹本身失去意义），而是在 `.gitattributes`
    里给 `*.csv` / `*.tsv` 加 `-text`：**指纹按字节算，数据文件就不许被 git 改写**。

    顺带确认了 bootstrap 的边界：除 `sync_video_assets.py`（字体副本不入库）外，
    两本书都能从零重建，`check_skills` 33 项全绿。这条流程已写进 README。

    教训：凡是有「按字节核对」「按 mtime 判新旧」这类判据的地方，都要假设
    **checkout 会改写字节**。判据越精确，对环境假设越敏感。

24. **第三本书开张，以及一条判据从「猜」改成「看」**（2026-10-25）

    `books/life`《生命的尺度》第一章换了第三种图形类型：**双对数散点**（横轴世代时间、
    纵轴成体体长）。三本书的图各有各的形状 —— 单轴台阶、平移曲线族、双轴散点 ——
    这不是风格选择，是「每个领域的尺度长什么样」逼出来的。

    结论本身也有意思：八个物种的体长跨近八个数量级、世代时间跨六个，而
    「体长 ÷ 世代时间」只跨 **1.9 个数量级**。九个点落在斜率≈1 的窄带上，
    说明**生物「长到自己那么大」的平均速度几乎不随体型变化**——体型变大只能靠时间变长补偿。

    **F3 判据的返工值得单独记。** 「死条目」原来是 grep 源码：把 id 的引号串数一遍，
    ≥2 次算用过。这在 `V(f"{cid}_size")` 这种动态拼接下**全线误报**（一次 18 条）。
    正确做法不是「把代码写得更啰嗦去讨好判据」，而是换观测方式：
    `Registry.items` 换成会记录读取的 dict，闸门**先把插图真跑一遍**，
    再判「这条登记有没有被读过」。

    | | 旧：grep 源码 | 新：运行时观测 |
    |---|---|---|
    | 判据基础 | 字符串计数（启发式） | 真实读取记录 |
    | 动态 id | 误报 | 正常 |
    | 代价 | 0 | 每本书多跑一次 `figures.build()`（< 1 秒） |

    换的时候还发现第二个隐患：`figures.py` 若自己 `importlib` 加载 `facts.py`，
    会得到**第二个 Registry**（插图读 A、闸门读 B，读取记录永远对不上）。
    统一改成走 `bookbuild.load_book_module` 并缓存同一实例。

    另外：改共享模块后要重建**所有**书，我手工 `cd` 到每本书漏了三次 ——
    现在有 `tools/build_books.py` 一条命令。

    **第 2 章（代谢）补记**：五个物种的体重与基础代谢率，对数—对数最小二乘
    拟合出斜率 **0.7505** —— 与 Kleiber 的 3/4 只差千分之一。图里同时画了
    「按表面积散热」预测的 2/3，两条线都过质心、只差斜率，在大象体重上分开 1.6 倍。
    这一章真正想教的不是 3/4，而是**「数据与幂律相容」不等于「规律被证明」**：
    五个点拟出精确到千分位的指数，很容易让人以为机制已经清楚，其实没有。

    F4 在这里抓出 30 处 `3/4`、`2/3` 这类分数的手写 —— 正好走 `subst_prose` 里
    早就留好的 `Fraction` 通路（渲染成 `3/4` 而不是 `0.75`）。**判据逼着作者
    用对了本来就有的机制**，这比单纯报错更有价值。

    **第 3、4 章补记**：第 3 章登记了「已被修正的说法」（细菌/细胞 10:1 → 1.3:1），
    并写明理由 —— *一个只收录正确答案的档案，没法教你判断下一次遇到的说法*。
    第 4 章把矛头转向对数轴自己：显生宙在线性轴上占 15%、在对数轴上占 88%，
    同一段历史宽度差 5.7 倍。**这本书用它自己的工具做了一次免责声明。**

    第 4 章还让渲染闸门抓到一个典型错误：`fig-deeptime` 写了 2 个步骤，
    但所有图层都没有 `when` 门控 —— 于是「逐档回放 2 步，画面指纹从不变化」。
    一个不改变画面的步骤控件，对读者就是一句谎话。修法是给第二行加 `k >= 2`，
    顺带让叙事变成「先看线性、再叠上对数」，比原来更清楚。

## 四、每项的硬门槛（与本项目既有纪律一致）

1. **不手写数字**：全部由 sympy 内核现算，答案卡 = 末步值 = 画板读数初值，四者同源。
2. **动画真跑**：数值积分/随机模拟必须真执行并录下步骤，不得编造轨迹。
3. **方向类结论现算**：不靠记忆（如洛伦兹力 `F=qv×B`、稳定性由特征值符号判）。
4. **出处分级**：每个数字标注「现算 / 实测 / 假设」，假设逐条列出。
5. **画板单参数契约**：一个滑块驱动，其余固定。
6. **题型数 ≥ 6**，且画板形态与既有技能可辨识地不同（否则应并入现有技能）。
